- Инструмент/версия: Semgrep CE, образ `semgrep/semgrep:1.175.0@sha256:b94b53d02fd4a022f9eac4e2af1380f5c3c4c21400e79d3336bdff1d1db5e796`. Gitleaks, образ `ghcr.io/gitleaks/gitleaks:v8.30.1@sha256:c00b6bd0aeb3071cbcb79009cb16a60dd9e0a7c60e2be9ab65d25e6bc8abbb7f`.
- Конфигурация/область: собственные правила лежат в `semgrep.yml` в корне репозитория, те их версия совпадает с версией объекта; правил четыре, запуск без доступа к сети. Общедоступные правила взяты из реестра Semgrep наборами `p/csharp`, `p/dockerfile`, `p/github-actions`, `p/secrets`, `p/security-audit` и `p/owasp-top-ten`, загружено 730 правил, к языкам проекта применимы 104. Список исключений Semgrep по умолчанию отменен намеренно, иначе каталог `tests` остался бы вне анализа. Gitleaks запускался дважды, в режиме `dir` по текущим файлам и в режиме `git` по всем коммитам всех веток с ключом `--log-opts=--all`; значения в отчетах маскируются ключом `--redact`.
- Воспроизведение: из корня репозитория `.\scripts\scan-sast.ps1 -Rules project -Label before`, `.\scripts\scan-sast.ps1 -Rules community -Label before`, `.\scripts\scan-secrets.ps1 -Mode tree -Label before`, `.\scripts\scan-secrets.ps1 -Mode history -Label before`. Запуск с общедоступными правилами требует сети, остальные три работают без нее. Все четыре завершились с кодом 0, что означает завершение сканирования, а не отсутствие дефектов.
- Первичный результат: [raw/semgrep-project-before.json](raw/semgrep-project-before.json), [raw/semgrep-community-before.json](raw/semgrep-community-before.json), [raw/gitleaks-tree-before.json](raw/gitleaks-tree-before.json), [raw/gitleaks-history-before.json](raw/gitleaks-history-before.json).
- Сигнал: собственные правила дали 3 сигнала. Правило `endpoint-opts-out-of-session-check` сработало в `src/SupportDesk.Api/Endpoints/AuthEndpoints.cs:16` и `src/SupportDesk.Api/Program.cs:73`, правило `unpredictable-value-source` в `tests/SupportDesk.Api.Tests/ApiFactory.cs:16`. Правила `ef-core-raw-sql` и `sensitive-value-in-log` не сработали ни разу. Общедоступные правила дали 0. Gitleaks дал 0 по текущим файлам и 0 по истории.
- Интерпретация: разбор каждого сигнала и его применимость записаны в [реестре находок](findings-register.md), записи F-01 и F-02. Оба сработавших правила широкие по замыслу, их сигнал означает требование разобраться, а не утверждение о дефекте. Ноль общедоступных правил означает, что эти 104 правила на этих 42 файлах совпадений не дали, и не означает отсутствия дефектов в продукте. Ноль у Gitleaks означает, что его правила не нашли совпадений ни в текущих файлах, ни в истории.
- Решение: подтвержденных дефектов нет. F-01 сохраняется с обоснованием, F-02 признан неприменимым в текущем контуре. Искусственный дефект ради получения находки не добавлялся.
- Изменение или отклонение: код по результатам этой проверки не менялся. Оба сигнала собственных правил сохранены осознанно, обоснования приведены в реестре. Остаточный риск состоит в том, что широкие правила продолжат срабатывать на этих же местах, и при каждом изменении обработчиков обоснование придется подтверждать заново.
- Объект после: тот же коммит `1c9bd54`, изменений не вносилось.
- Проверки: отдельные проверки под эту цепочку не требовались, тк код не менялся. Состояние продукта на этой версии подтверждено прогоном `dotnet test`, 8 тестов из 8.
- Rerun: повторный запуск не требовался, тк ни код, ни конфигурация анализа по результатам этой проверки не менялись. Повтор потребуется при изменении обработчиков, при добавлении правил и при появлении новых файлов в области анализа.
- Ограничения вывода и пересмотр: общедоступные наборы правил подтягиваются из реестра Semgrep и не закреплены по версии, поэтому повтор через некоторое время может дать другой состав правил; по версии закреплен только образ сканера. Правила Gitleaks рассчитаны на известные форматы токенов и строки с высокой энтропией, поэтому осмысленная фраза в роли пароля ими не обнаруживается. Конкретный пример в этом репозитории, строка `UserPassword` в `tests/SupportDesk.Api.Tests/ApiFactory.cs`, Gitleaks не нашел; это граница его правил, а не отсутствие строки. Semgrep анализирует только файлы, отслеживаемые git, поэтому локальный `.env` в область не входит и входить не должен. Поиск по истории охватывает историю этого репозитория и ничего не говорит о значениях, которые могли существовать вне него. Пересмотр нужен при смене набора правил, при обновлении инструментов и при появлении в проекте работы с сырым SQL или с внешними ключами.
